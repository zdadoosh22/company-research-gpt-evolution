## Adapter contract

`tools/scoped_research_adapter.py` exposes `validate_package(root, job)`, `validate_output(result, job, root)` and `run_scoped_job(root, job, ...)`. An explicit caller supplies one frozen package. Analysis requests `gpt-6.1-sol`; review requests `gpt-6-astra`; both request high reasoning and standard service. Unsupported models, authentication failures, quota exhaustion and timeouts are visible failures with a saved continuation and exponential retry suggestion. There are no internal retries.

The JSON package has exactly `job_id`, `role` (`analysis` or `review`), `as_of` (timezone-qualified), `scope` with `required_categories`, `methodology` with `base` and `scoped` path/SHA256 bindings, `sources`, and a `target` path/SHA256 binding. Base methodology must match `methodology/current.json`. The scoped method allowlist currently contains only `monitoring/DECISION-SCOPE.md`; changing it is an explicit implementation change. All paths resolve within this project and reject known credential locations. Evidence/target/method hashes are checked before invocation and after completion.

Each source supplies `source_id`, `path`, `sha256`, `published_at`, `accessed_at`, and nonempty exact `read_locations`. Known publication/access records may retain an ISO date when the archive records only the day; chronology comparisons use the end of that UTC day conservatively, without claiming an exact access time. Exact timestamps require a timezone. Unknown publication dates remain null and additionally require `date_status: "publication-date-unknown-snapshot"` plus an exact timezone-qualified `captured_at`, no later than both job as-of and access. These snapshots prove captured bytes only, not first-publication time or historical consensus cutoff. They cannot be relabelled as known publication records while retaining unknown-date fields. All source locations are supplied provenance assertions; deterministic checks do not prove that a model actually read them or that their contents support a claim.

Before any subprocess, request, schema and metadata are saved atomically. Before model execution, the authenticated in-progress checkpoint is saved. Provider/notification credentials are removed from the child environment; ChatGPT authentication is forced and user provider configuration ignored. Raw tool transcripts and stderr are not persisted. Accepted output and a reduced lifecycle/usage audit are saved; transient candidate output is removed on ordinary completion/failure. An abrupt process or machine termination can leave transient candidates, which are never accepted merely because present.

Output contains typed `findings`, `coverage`, `sources`, `gaps`, `conclusions` and `continuation`. Numerical inputs distinguish reported/guidance/assumption/calculation/missing; missing values remain null and affected conclusions are withheld. Material unresolved findings/gaps block their affected conclusions and prevent complete status. Complete statuses are role-specific `scoped-analysis-complete` and `review-complete`; other outputs are `partial` or `withheld`. Structured trading authority fields do not exist; adapter metadata always keeps actionable, analytical approval and gate activation false. Text checks are conservative guards, not semantic certification or a guarantee against all possible secret-like text.

Requested model, configured reasoning/speed and observed lifecycle identity are separate. An exact requested route that successfully completes with no observed substitution can produce `review-complete` even when CLI events do not report a backend model name. In that case `actual_model` remains null, `actual_model_verification` remains `not-reported`, and `backend_independently_verified` remains false. `independent_review` describes the separate requested reviewer job; it is not an Astra certification or investment approval. A conflicting reported model is rejected. Acceptance of analytical review belongs to the separate review workflow.

## Explicit durable queue

`tools/scoped_research_queue.py` owns only `state/scoped-research/queue.sqlite`, an OS worker lock and per-job adapter checkpoints under that same isolated directory. Enqueue and status calls make no model requests. `run-one` attempts at most one due job and exits: there is no timer, scheduled task, background worker, live-service integration or automatic retry. One process lock spans selection and execution. An identical job ID/package is idempotent; different bytes under the same ID are rejected. Revalidating a package detects changed sources, target or methodology before any model call.

Queue states are queued, running, complete, deferred and needs-input. Quota/auth/model/process failures save visible reasons and retry times; another explicit call after that time is required. Valid partial/withheld analytical outputs become needs-input rather than repeatedly consuming model quota. Corrected evidence or revised scope requires a new frozen package and job ID. Attempts are capped at 100. A crashed worker releases its OS lock; the next explicit call recovers completed checkpoints only after verifying contained result paths, result hashes, output schema, frozen package hash and current input hashes. Missing/tampered completed results become needs-input. An incomplete interrupted attempt is deferred for at least 60 seconds, with no immediate repeat.

Examples from the project root, using the bundled Python executable in place of `python` where needed:

```powershell
python -B tools/scoped_research_queue.py enqueue validation/scoped-jobs/jpm-20261008-frozen-astra-review-v2.json
python -B tools/scoped_research_queue.py status
# Explicit model-work opt-in: one due job only.
python -B tools/scoped_research_queue.py run-one
```

The prepared JPM package is validated but has not been enqueued or executed. It binds the original 8 October JSON dossier, the approved base and scoped design, and 12 hash-matched local source archives including unknown-publication-date price, expectations and submissions snapshots. It preserves the dossier's declared read locations. Sources with failed/no local archives (the alternate event host, TipRanks and July financing filing) remain limitations in the unchanged dossier; the issuer-domain event archive is available separately. Earlier overwritten dividend/price snapshots are not claimed restored: the package binds the later verified bytes recorded in the dossier. Independent review must inspect these limits and the supplied target rather than inherit its conclusion. This package freezes historical analysis; it does not claim current price/event/news freshness.

Parent integration then updated the implementation-status paragraph in DECISION-SCOPE.md. The original frozen v1 request correctly fails its old scoped-file hash and remains preserved. The replacement v2 request binds the current bytes and was separately validated against all 15 files. Neither request was enqueued or run. Use v2 while its bindings remain current; any later change requires a newly versioned package rather than bypassing the verifier.

## Verification and remaining limits

Verification on 9 October passed 28 focused adapter/queue tests and the complete 289-test project suite. Focused tests inject a fake subprocess or adapter and use temporary databases. They exercise subscription-only arguments, checkpoints, auth/model/quota/timeout failure, backoff, partial results, missing identity, model substitution, target mutation, path escape, source chronology, snapshot date contracts, numerical unknowns, material blockers, credential rejection, durable enqueue/idempotency, one-job execution, concurrency locking, interruption recovery and missing/tampered recovery results. These tests consume no model quota and make no broker or live observation database calls.

CLI availability was checked, but a real model call on a validated package remains unperformed in this adapter validation. Deterministic validation checks structure, file hashes and declared provenance; it cannot prove financial facts, actual reading, complete discovery, independent backend identity or analytical sufficiency. The read-only sandbox governs model-generated writes but is not a filesystem read allowlist. Credential-like output rejection is bounded rather than a general content-security proof. A machine interruption between model completion and a durable final checkpoint can require a later explicit retry and duplicate model work; saved available results are recovered where verifiable. These limitations remain visible and do not create trading authority.
