# Research and follow-up workflow

## Full thesis
1. Load AGENTS.md, approved methodology, principles and relevant history. Record the request and methodology hash in a new run.
2. Resolve legal entity, listing, class, currency, fiscal year, ownership basis and dated price. Locate latest annual/interim disclosures and subsequent material events. Never label delayed data live.
3. Build the evidence register and historical data. Prefer free original documents; read cited passages and record pages/sections. Collect contrary evidence and relevant investor theses as opinions. Investigate accounting/period conflicts rather than asking an LLM to guess their explanation.
4. Select sector modules, identify decisive variables and causal drivers, evaluate accounting, financing, governance, competition and capital allocation. Use the complete methodology's coverage ledger.
5. Build causally distinct bear/base/bull forecasts. Use a justified valuation method and cross-check. Reconcile current and future values, funding, equity claims and returns. Keep sources and historical actuals separate from forecasts. Investigate source gaps; withhold affected conclusions where required.
6. Conduct an adversarial review of evidence, assumptions and arithmetic. Record material issues and resolutions. Stronger-model review is a real labelled step, never a fictitious certification.
7. Author the standalone thesis, full analysis and Excel workings. The full report begins with the thesis. Link material claims to sources and calculations. Render PDFs and workbook views. Recalculate and verify representative input changes in temporary copies. Do not substitute a static sensitivity grid for a promised editable grid.
8. Validate acceptance, freeze reported inputs, create a publication hash manifest and update the company index. A partial run remains partial and carries a precise continuation point. Do not promise background continuation.

## Focused question
Load the relevant report and evidence, identify whether freshness affects the answer, refresh only necessary sources and answer directly. Save a focused note only when it changes the research record or provides useful new evidence. Do not regenerate a full thesis for a terminology question.

## Comparison
Create a dated comparison record linking each company run. Align as-of dates, reporting bases, security currencies and economically useful measures. Explain differences that cannot be normalised. Do not invent rankings or average incompatible valuations.

## Update
Create a new dated run referencing its predecessor. Refresh latest disclosures, price and changed thesis variables. Preserve previous actuals; clearly distinguish restated history. Provide a sourced change note and new workbook when assumptions/results change. Reissue the thesis if central judgement materially changes. Regenerate the complete report only when requested or required to communicate a major re-underwriting. Update the index only after checks.

## Currency, timing and maturity
Forecast in reporting currency and bridge to trading currency at an explicitly sourced date/rate if different. Returns use the security's trading currency; explain investor FX exposure. Use a five-year horizon by default, actual dated cash flows for distributed dividends and a longer business transition where required. Use a fractional initial period when valuation date and fiscal year-end differ; never pretend the next calendar year-end is exactly one year away.

## What-if workbook
Reported cases are frozen originals; What-if starts from Base and is separately editable. Scenario comparison is evaluated from the same model logic. In the starter workbook, reported comparison values are dated snapshots and the active/What-if build recalculates. Rebuild the snapshot comparison after approved model changes. Keep the refresh method visible. For simultaneous live case comparisons, use explicit scenario schedules only when requested and tested, rather than disguising snapshots as live results.
