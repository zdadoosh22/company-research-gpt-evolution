# Model choice and stronger review

Start validation with GPT-6.1 Sol High, Standard speed. Do not claim or change a model setting without verification. Model labels in run records describe actual settings where known; unknown settings stay unknown. Fast mode is unnecessary when working speed is unimportant.

The pilot evidence package contains the actual documents/locations, reconciled inputs, selected methods, forecasts, reviewed model results, opposing evidence and unresolved issues. Ask Astra to challenge the present-to-horizon bridge, dividends/dilution, sector substitutions, missing foundations and evidence-to-conclusion consistency. Do not request cosmetic rewriting.

The review must be performed by Astra and identify findings, severity, evidence, proposed correction and outcome. Self-review is separate. If an Astra route is unavailable or delegation has not been authorised, mark stronger review pending. Never label a Sol pass as independent or Astra review.

Record account-level usage snapshots where available and the actual workload between them. These are not precise per-stage costs. Accept a Sol-led workflow only if pilot review finds no recurring unresolved material omissions/errors; otherwise escalate the affected stages. Routine focused questions use Sol unless their complexity warrants otherwise.

Audit request: Review the supplied evidence and calculations without assuming the reported conclusion is correct. Identify concrete material defects, especially timing, distributions, ownership claims, sector economics and unsupported evidence. Distinguish verified defects from alternative assumptions and requests for more evidence. Return findings, calculation checks, justified fixes and remaining limitations. Preserve sound requirements; do not rewrite for style.
